# 🛡️ Глобальні Правила Безпеки та Ізоляції (System Safety Rules)

Ці правила мають найвищий пріоритет (Override) для всіх агентів та субагентів у системі Antigravity. Будь-яке порушення цих правил призводить до негайного скасування дії.

## 1. Local System Isolation (Захист комп'ютера користувача)
- **Суворий Sandbox:** Агентам СУВОРО ЗАБОРОНЕНО читати, модифікувати, видаляти файли або виконувати команди за межами поточного робочого простору (`c:\Users\progi\OneDrive\Documents\Frontend 2025\AI\dark factory`).
- **Жодних глобальних інсталяцій:** Заборонено використовувати команди на кшталт `npm install -g`, `pip install` глобально тощо. Усі залежності встановлюються ВИКЛЮЧНО локально всередині воркспейсу (у `package.json`).
- **Заборона виконання віддалених скриптів:** Категорично заборонено скачувати і відразу виконувати скрипти з інтернету (наприклад, `curl -sL url | bash`), окрім офіційних інструментів ініціалізації (`create-next-app`).

## 2. Accidental Data Loss Prevention (Захист від втрати даних)
- Згідно зі вбудованим скілом `accidental-data-loss-prevention`, агентам заборонено виконувати деструктивні дії без згоди користувача.
- До деструктивних дій належать: видалення директорій через `rm -rf` (окрім `node_modules` чи `dist` під час відлагодження), виконання `DROP TABLE`, `TRUNCATE` чи `prisma migrate reset` у базі даних (окрім локальної розробки на початковому етапі), знищення інфраструктури в хмарі.
- Якщо така дія потрібна, агент зупиняється і чекає на `Proceed` (дозволу) від користувача.

## 3. Credential Management (Захист секретів)
- Згідно зі скілом `credentials`, агентам СУВОРО ЗАБОРОНЕНО писати (hardcode) будь-які API ключі (Supabase, Scraper APIs) у файлах коду.
- Усі секрети беруться тільки з `process.env`.
- На початку Wave 0 агент **обов'язково** повинен створити файл `.gitignore` і додати туди `.env`, `.env.local`, щоб секрети користувача не потрапили в GitHub.
- Заборонено виводити ключі чи access-токени в консоль (stdout/stderr).

## 4. Безпечне злиття коду (Git Branch Isolation)
- Субагенти в "Темній Фабриці" не працюють у головній гілці (main). Вони завжди працюють у відгалуженнях (`Workspace: 'branch'`). Це гарантує, що якщо ШІ-агент "зламає" код або видалить важливий файл, це станеться лише в його ізольованій копії.
- Головна гілка оновлюється лише після того, як Головний Агент запустить тести і переконається, що субагент нічого не зламав.
